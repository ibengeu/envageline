🍇 Low-hanging fruit

Start here

Small, isolated additions to the existing normalizePdfText / chunking pipeline in app.js. Each is a self-contained regex or detection pass — no architecture change, no UI work.

FeatureWhy it's cheapCurrent statusEffort
Suppress raw URLs Single regex pass before chunking. No detection ambiguity — URLs have a fixed shape. Not implemented XS
Suppress citation markers [12] Same shape as URL suppression — one more regex in normalizePdfText. Not implemented XS
Strip confidently-detected page numbers Standalone numeric lines at paragraph boundaries are a narrow, testable pattern. Not implemented S
Remove repeated headers/footers Detect lines repeating identically across page boundaries in the raw extraction; drop duplicates. Not implemented S
"Evangeline forgets your document" messaging Copy-only change to index.html/status line — the no-history behavior already exists, it's just not communicated. Behavior exists, not stated XS
Show local-processing flow (PDF → Browser → Speaker) Small UI addition near the drop zone. Reinforces the privacy claim that's already true architecturally. True today, not shown XS

🧭 Bigger bets

Next

Real detection logic or UI restructuring. Worth sequencing after the quick regex wins land and prove out the pipeline approach.

FeatureWhy it's harderCurrent statusEffort
Heading detection + natural pauses Needs font-size/style signal from the PDF layer, not just text — heavier than a text-only regex. Not implemented M
References/bibliography detection + stop-before option Requires a heuristic classifier (heading text match + density of citation-like lines), then a playback branch. Not implemented M
Separate handling for figure/table captions Needs layout-aware extraction to distinguish captions from body text, plus a distinct read-aloud treatment. Not implemented M
Safe fallback for tables/equations/malformed text Needs a "don't read this literally" detector plus a spoken placeholder — a new code path, not a filter. Not implemented M
Minimal player UI (voice/pitch/rate → advanced settings) Restructuring existing markup/CSS, not new logic — but touches the primary screen, so needs care. Inverse of plan today M

⚠️ Scope drift to resolve

Decide

The shipped app already does things the plan says v1 should not do. Worth a deliberate call — keep and update the plan, or trim to match it — rather than leaving the mismatch implicit.

FeatureWhat the plan saysWhat's shipped
EPUB support "Explicitly out of scope for v1" — plan wants PDF-only focus. epub-engine.js + full extraction pipeline exists
Voice / rate / pitch controls Plan wants these moved out of the primary interface into "advanced settings." Currently in main document-controls panel
Document stats panel (pages/words/filename) Plan's Minimal Player UI lists only play/pause/skip/speed/section/time-remaining. Extra stats block shown by default
